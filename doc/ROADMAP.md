# Roadmap - План развития ETL Engine

Данный документ описывает задачи по развитию ядра ETL движка для обеспечения надежности, производительности и удобства использования.

## Критичные задачи (высокий приоритет)

### 1. Структурированная обработка ошибок

**Проблема:** Сейчас все ошибки оборачиваются в `RuntimeException` без структуры.

**Требуется:**
- Создать иерархию исключений движка:
  - `EtlException` (базовый класс)
  - `ExtractionException` (ошибки извлечения)
  - `TransformationException` (ошибки преобразования)
  - `LoadingException` (ошибки загрузки)
- Добавить контекст ошибки (этап выполнения, jobId, проблемная запись)
- Классификация ошибок (критическая/некритическая)
- Возможность продолжить выполнение при некритических ошибках
- Dead Letter Queue для проблемных записей

**Файлы для изменения:**
- `src/main/java/ru/pospelov/etl/engine/engine/EtlPipelineFactory.java`
- Все компоненты (Extractor, Transformer, Loader)
- Создать пакет `ru.pospelov.etl.engine.exception`

### 2. Метрики и статистика выполнения

**Проблема:** Нет способа получить информацию о прогрессе выполнения.

**Требуется:**
- Создать интерфейс `EtlMetrics` или callback для метрик
- Добавить события выполнения:
  - `onExtractStart`, `onExtractComplete`
  - `onTransformStart`, `onTransformComplete`
  - `onLoadStart`, `onLoadComplete`
  - `onRecordProcessed`
- Статистика выполнения:
  - Количество обработанных записей
  - Время выполнения по этапам
  - Количество ошибок
  - Скорость обработки (строк/сек)
- Возможность подписки на события извне (через интерфейс)
- Статусы выполнения:
  - Создать `EtlJobStatus` с состояниями (pending/running/extracting/transforming/loading/completed/failed/cancelled/timeout)
  - Вызывать события смены статуса через метрики
  - API для получения текущего статуса и истории статусов по jobId

**Файлы для изменения:**
- Создать `ru.pospelov.etl.engine.metrics.EtlMetrics`
- Создать `ru.pospelov.etl.engine.metrics.EtlMetricsCollector`
- Модифицировать `EtlPipeline` для поддержки метрик

### 3. Отмена выполнения (Cancellation) ✅

**Проблема:** Нет способа остановить выполняющуюся задачу.

**Требуется:**
- ✅ Добавить `CancellationToken` или `AtomicBoolean` для проверки отмены
- ✅ Передавать токен отмены через все этапы
- ✅ Добавить проверку отмены в циклах обработки данных
- ✅ Обеспечить корректное завершение потоков при отмене
- ✅ Очистка ресурсов при прерывании выполнения
- ✅ Метод `cancel()` в `EtlPipeline`

**Реализовано:**
- Создан `ru.pospelov.etl.engine.engine.CancellationToken` - thread-safe токен для отмены
- Создан `ru.pospelov.etl.engine.engine.CancellationException` - исключение при отмене
- Модифицирован `EtlPipeline` - добавлены методы `cancel()` и `isCancelled()`
- Обновлен `StructuredEtlPipeline` - добавлены проверки отмены на всех этапах
- Добавлены проверки отмены в циклах transform и load
- Статус `CANCELLED` отражается в метриках
- Токен отмены автоматически сбрасывается при новом запуске `run()`

**Файлы:**
- `src/main/java/ru/pospelov/etl/engine/engine/CancellationToken.java`
- `src/main/java/ru/pospelov/etl/engine/engine/CancellationException.java`
- `src/main/java/ru/pospelov/etl/engine/engine/EtlPipeline.java`
- `src/main/java/ru/pospelov/etl/engine/engine/EtlPipelineFactory.java`
- `src/test/java/ru/pospelov/etl/engine/EtlPipelineCancellationTest.java`

### 4. Валидация параметров задачи

**Проблема:** Параметры проверяются только при использовании, нет централизованной валидации.

**Требуется:**
- Создать интерфейс `JobValidator` для валидации `EtlJob`
- Валидация обязательных параметров для каждого типа компонента
- Проверка типов параметров
- Валидация доступности компонентов (extractor/transformer/loader)
- Понятные сообщения об ошибках валидации
- Валидация перед созданием пайплайна

**Файлы для изменения:**
- Создать `ru.pospelov.etl.engine.validation.JobValidator`
- Создать валидаторы для каждого типа компонента
- Модифицировать `EtlPipelineFactory` для валидации

## Важные задачи (средний приоритет)

### 5. Потоковая обработка (Streaming) ✅

**Проблема:** Все данные загружались в память (`Collection<EtlRecord>`), что при больших объемах данных (> 1M записей) приводило к чрезмерному потреблению памяти.

**Реализовано:**
- ✅ Изменен интерфейс `Extractor` на callback-based подход с `Consumer<Collection<EtlRecord>>`
- ✅ Батчевая обработка данных - данные обрабатываются порциями (по умолчанию 50,000 записей)
- ✅ Streaming pipeline в `EtlPipelineFactory` - каждый батч проходит через extract → transform → load
- ✅ Параметр `streamBatchSize` для настройки размера батча
- ✅ Значительное снижение потребления памяти (вместо всех данных в памяти - только текущий батч от каждого потока)
- ✅ Сохранена многопоточность и производительность
- ✅ `FastSqlServerLoader` продолжает использовать bulk insert
- ✅ Все существующие тесты проходят успешно

**Преимущества:**
- Память: вместо 1M записей в памяти одновременно - только `threads * streamBatchSize` (например, 4 * 50K = 200K)
- Скорость: параллельная обработка сохранена, загрузка начинается сразу при извлечении первого батча
- Гибкость: размер батча настраивается через параметры задачи

**Файлы:**
- `src/main/java/ru/pospelov/etl/engine/steps/extractor/Extractor.java`
- `src/main/java/ru/pospelov/etl/engine/steps/extractor/JdbcExtractor.java`
- `src/main/java/ru/pospelov/etl/engine/steps/extractor/KafkaExtractor.java`
- `src/main/java/ru/pospelov/etl/engine/steps/loader/JdbcLoader.java`
- `src/main/java/ru/pospelov/etl/engine/steps/loader/KafkaLoader.java`
- `src/main/java/ru/pospelov/etl/engine/steps/loader/FastSqlServerLoader.java`
- `src/main/java/ru/pospelov/etl/engine/engine/EtlPipelineFactory.java`
- `src/main/java/ru/pospelov/etl/engine/validation/ExtractorValidator.java`

### 6. Контекст выполнения

**Проблема:** Нет способа передать контекст между этапами.

**Требуется:**
- Создать `EtlExecutionContext` с метаданными выполнения
- Передача контекста через все этапы (extract → transform → load)
- Возможность сохранять промежуточные данные в контексте
- Метаданные: jobId, executionId, timestamp, параметры

**Файлы для изменения:**
- Создать `ru.pospelov.etl.engine.engine.EtlExecutionContext`
- Модифицировать интерфейсы компонентов для приема контекста
- Обновить `EtlPipeline` для передачи контекста

### 7. Таймауты

**Проблема:** Нет ограничений по времени выполнения.

**Требуется:**
- Таймауты на этапы (extract/transform/load)
- Таймауты на отдельные операции
- Автоматическая отмена при превышении таймаута
- Настройка таймаутов через параметры задачи

**Файлы для изменения:**
- Добавить параметры таймаутов в `EtlJob`
- Реализовать проверку таймаутов в `EtlPipeline`
- Использовать `CompletableFuture` с таймаутами

### 8. Типизация параметров

**Проблема:** Все параметры как `Object`, нет валидации типов.

**Требуется:**
- Типизированные геттеры в `EtlJob`:
  - `getIntParam(String key)`
  - `getStringParam(String key)`
  - `getBooleanParam(String key)`
  - `getLongParam(String key)`
  - `getDoubleParam(String key)`
- Валидация типов с понятными ошибками
- Значения по умолчанию с типами
- Опциональные параметры

**Файлы для изменения:**
- Модифицировать `ru.pospelov.etl.engine.model.EtlJob`
- Обновить все использования параметров в компонентах

## Желательные задачи (низкий приоритет)

### 9. Хуки/события (Lifecycle hooks)

**Проблема:** Нет возможности перехватывать события выполнения.

**Требуется:**
- Создать интерфейс `EtlLifecycleListener`
- События:
  - `beforeExtract(EtlJob job)`
  - `afterExtract(EtlJob job, Collection<EtlRecord> records)`
  - `beforeTransform(EtlJob job, Collection<EtlRecord> records)`
  - `afterTransform(EtlJob job, Collection<EtlRecord> records)`
  - `beforeLoad(EtlJob job, Collection<EtlRecord> records)`
  - `afterLoad(EtlJob job)`
- Возможность модифицировать данные через хуки
- Регистрация нескольких слушателей

**Файлы для изменения:**
- Создать `ru.pospelov.etl.engine.engine.EtlLifecycleListener`
- Модифицировать `EtlPipeline` для поддержки слушателей

### 10. Транзакционность (для Loader)

**Проблема:** Нет поддержки транзакций для SQL Loader.

**Требуется:**
- Опция транзакционной загрузки
- Rollback при ошибках
- Batch commit для больших объемов
- Настройка через параметры задачи

**Файлы для изменения:**
- Модифицировать `JdbcLoader` и `FastSqlServerLoader`
- Добавить параметры транзакций в `EtlJob`

### 11. Структурированное логирование

**Проблема:** Есть базовое логирование, но нет структуры.

**Требуется:**
- MDC (Mapped Diagnostic Context) с jobId, executionId
- Структурированные логи (JSON формат)
- Уровни логирования на этапах
- Контекстные логи с метаданными

**Файлы для изменения:**
- Настроить MDC в `EtlPipeline`
- Добавить структурированное логирование через SLF4J
- Обновить все компоненты для использования MDC

### 12. Обработка пустых результатов

**Проблема:** Частично есть, но не системно.

**Требуется:**
- Единая стратегия обработки пустых результатов
- Опция пропускать пустые результаты или выбрасывать ошибку
- Логирование пустых результатов
- Настройка через параметры задачи

**Файлы для изменения:**
- Добавить параметр `emptyResultStrategy` в `EtlJob`
- Реализовать обработку в `EtlPipeline`

### 13. Обработка null значений

**Проблема:** Частично есть, но не системно.

**Требуется:**
- Стратегии обработки null (пропустить/заменить/ошибка)
- Настройка на уровне задачи
- Валидация null значений
- Замена null на значения по умолчанию

**Файлы для изменения:**
- Добавить параметры обработки null в `EtlJob`
- Реализовать обработку в трансформерах

### 14. Проверка доступности компонентов

**Проблема:** Ошибка возникает только при выполнении, если компонент не найден.

**Требуется:**
- Проверка доступности компонентов при создании пайплайна
- Понятные ошибки с перечислением доступных компонентов
- Валидация совместимости компонентов
- Метод получения списка доступных компонентов

**Файлы для изменения:**
- Модифицировать `EtlComponentRegistry` для получения списка компонентов
- Добавить валидацию в `EtlPipelineFactory`

### 15. Ресурсы и управление соединениями

**Проблема:** Управление ресурсами разрозненное.

**Требуется:**
- Централизованное управление соединениями
- Connection pooling для параллельных операций
- Автоматическое закрытие ресурсов
- Мониторинг использования соединений

**Файлы для изменения:**
- Создать `ru.pospelov.etl.engine.resources.ConnectionManager`
- Обновить компоненты для использования централизованного управления
