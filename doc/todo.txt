 Особенности конфигурации

 Kafka Connect S3 Sink

 - Flush strategy: 50,000 записей ИЛИ 5 минут (что наступит раньше)
 - Расчёт размера файла: 31 поле × ~200 байт × 50,000 записей ÷ Snappy ≈ 150-200 MB
 - Error handling: Fail-fast (errors.tolerance: none) для начала
 - Offset commit: Только после успешной записи в S3
 - Consumer overrides: max.poll.records=5000, auto.offset.reset=earliest

 Trino Memory Configuration

 - Query max memory: 4GB
 - Query max memory per node: 2GB
 - JVM heap: 8GB

 MinIO

 - Access Key: minioadmin
 - Secret Key: minioadmin
 - Bucket: datalake
 - Region: us-east-1
 - Path-style access: enabled

 Troubleshooting

 Проблема: Коннектор не стартует

 Решение:
 - Проверить логи: docker-compose logs kafka-connect
 - Убедиться, что MinIO доступен: docker exec kafka-connect curl http://minio:9000/minio/health/live
 - Проверить синтаксис JSON конфигурации

 Проблема: Нет Parquet файлов в MinIO

 Решение:
 - Проверить, есть ли данные в топике order-events (AKHQ)
 - Проверить статус задач: curl http://localhost:8083/connectors/s3-sink-order-events/tasks
 - Подождать 5 минут (rotate.interval.ms)

 Проблема: Файлы слишком маленькие (<10 MB)

 Решение:
 - Увеличить flush.size до 100,000-200,000
 - Увеличить rotate.interval.ms до 600,000 (10 минут)

 Проблема: Trino не может прочитать файлы

 Решение:
 - Проверить credentials в minio.properties
 - Проверить путь в CREATE TABLE statement
 - Протестировать доступ: docker exec -it <trino-container> curl http://minio:9000/
